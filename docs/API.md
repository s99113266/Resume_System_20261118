# API（資料說明）

> 目的：記錄 API 網址、傳輸封包結構，以及「哪個欄位的哪個值會執行哪個動作」。
>
> 存取原則：讀取一次讀回整份合輯；儲存一次送出整份合輯。儲存時封包內含一個隱藏動作欄位，說明本次是新增、修改、刪除或其他。
>
> 未來前端 JS 依本文件撰寫，不得自行定義不同規則。
>
> 限制：本文件禁止寫 JSON 或程式碼，一律用文字與表格描述。
>
> 狀態：後端尚未實作；網址、動作值與後端行為皆為設計值，實作後必須更新本文件，並在當日日誌留下紀錄。

## 1. 端點（假設）

| 方法 | 網址（假設） | 用途 | 送出內容 | 成功條件 | 失敗條件 | 前端呼叫端 |
| ---- | ------------ | ---- | -------- | -------- | -------- | ---------- |
| GET | api/resume | 一次讀回整份履歷合輯 | 無，只有請求 | 資料存在、可讀且可解析；回成功旗標 true 與完整合輯 | 資料不存在、解析失敗、讀取例外；回成功旗標 false | js/api.js 的讀取函式 |
| PUT | api/resume | 一次送出整份合輯與隱藏動作欄位 | 隱藏動作欄位＋9 個資料區段（同層） | 動作值合法、合輯通過格式檢查且寫入成功 | 動作值不合法、格式檢查不通過、寫入失敗 | js/api.js 的儲存函式 |

補充：

- 一次操作只呼叫一個端點，不提供單一區段的讀取或寫入。
- 讀取與儲存都只呼叫一次，不得先送部分區段再補送。
- 回應格式只有成功旗標，見第 6 節。
- 瀏覽頁的讀取順序：後端 API 優先；後端尚未實作或讀取失敗時，改讀 data/resume.json 作為預覽資料（只讀，不寫入）。
- 儲存函式與動作欄位屬編輯頁階段，尚未建立。

## 2. 傳輸封包結構

儲存時送出的封包，由「隱藏動作欄位」與「9 個資料區段」組成，全部位於同一層。

| 位置 | 內容 | 型別 | 說明 |
| ---- | ---- | ---- | ---- |
| 同層 | 隱藏動作欄位（action） | 文字 | 值為新增、修改、刪除、其他其中之一，見第 3 節 |
| 同層 | basicInfo | 物件 | 基本資料＋聯繫方式 |
| 同層 | education | 清單 | 學歷 |
| 同層 | experience | 清單 | 經歷 |
| 同層 | portfolio | 清單 | 作品集（暫時保留，送出空清單） |
| 同層 | skills | 文字清單 | 技能 |
| 同層 | certificates | 清單 | 證照／證書 |
| 同層 | desiredPositions | 文字清單 | 希望職缺 |
| 同層 | introduction | 文字 | 中文簡介 |
| 同層 | introductionEn | 文字 | 英文簡介 |

封包規則：

1. 不再額外包一層容器；動作欄位與 9 個區段並列，因此資料仍維持 3 層以內。
2. 動作欄位不屬於履歷資料：後端必須先取出、驗證，再丟棄；存檔內容不得包含動作欄位。
3. 讀取回來的合輯不含動作欄位；前端不得假設讀回的資料有動作欄位。
4. 封包內不得出現上述以外的欄位，避免與履歷資料混淆。
5. 每個區段每次都要完整送出；即使該區段沒有修改，也要帶上目前內容。

## 3. 動作欄位規格

動作欄位由編輯頁的隱藏欄位提供，值只接受下列四種。

| 值 | 意義 | 前端何時設定 | 後端行為 | 回應成功旗標 |
| -- | ---- | ------------ | -------- | ------------ |
| 新增 | 建立原本不存在的履歷資料 | 讀取失敗畫面選擇「建立新履歷」後送出 | 建立資料並寫入 9 個區段 | true |
| 修改 | 覆蓋既有履歷資料 | 編輯頁預設值；按下「儲存」時送出，包含清單項目的新增、刪除、排序與欄位修改 | 以送出的 9 個區段整份覆蓋 | true |
| 刪除 | 刪除整份履歷資料 | 按下「刪除整份履歷」並完成二次確認後送出 | 不採用送出的內容，將資料清除回空白範本 | true |
| 其他 | 保留給未來操作，目前沒有對應用途 | 目前不使用 | 不變更任何資料 | false |
| 未提供或不在清單 | 無效的請求 | — | 不變更任何資料 | false |

補充規則：

1. 編輯頁載入成功時，動作欄位預設為「修改」。
2. 讀取失敗時的畫面提供「重新載入」與「建立新履歷」；只有選擇後者才送出「新增」。
3. 清單項目層級的新增或刪除仍屬於「修改」，因為每次送出的都是一整份合輯。
4. 動作值的合法清單由 js/rules.js 定義（編輯頁階段建立），js/edit.js 負責設定，js/api.js 負責放入封包送出。
5. 後端必須先檢查動作值，再檢查資料格式；動作值不合法時不得寫入任何資料。
6. 「其他」目前一律回失敗，避免未知操作誤寫資料；若要啟用，必須先更新本文件與 js/rules.js。

## 4. 讀取流程（一次讀取，拆成頁面區塊）

| 步驟 | 執行者 | 動作 | 檔案 |
| ---- | ------ | ---- | ---- |
| 1 | 頁面載入 | 呼叫讀取端點，只呼叫一次 | index.html、edit.html |
| 2 | js/api.js | 取得成功旗標與整份合輯；後端不可用時改讀範例資料檔 | js/api.js |
| 3 | 單頁 JS | 依區段把整份合輯拆成頁面各區塊，拆分只存在記憶體、不改變資料結構 | js/edit.js、js/view.js |
| 4 | 各區塊 | 只顯示或編輯自己負責的欄位，不得直接呼叫 API | js/edit.js、js/view.js |
| 5 | 讀取失敗時 | 不拆解、不渲染；顯示讀取失敗訊息、重新載入與建立新履歷 | js/ui.js、js/edit.js |

區段與頁面區塊對照：

| 區段 | 編輯頁區塊 | 檢視頁區塊 |
| ---- | ---------- | ---------- |
| basicInfo | 基本資料表單（姓名、生日、身分證字號、照片網址、性別、手機、信箱） | 頁首（照片、姓名、手機、信箱） |
| education | 學歷清單 | 學歷區段 |
| experience | 經歷清單 | 經歷區段 |
| portfolio | 不顯示（暫時保留） | 作品集空狀態 |
| skills | 技能輸入與標籤 | 技能標籤 |
| certificates | 證照清單 | 證照區段 |
| desiredPositions | 希望職缺輸入與標籤 | 頁首職缺標籤 |
| introduction | 中文簡介多行輸入 | 簡介切換 |
| introductionEn | 英文簡介多行輸入 | 簡介切換 |

拆分規則：

1. 拆分只是把同一份合輯的指標分給各區塊，不複製格式、不改變結構。
2. 每個區塊只讀寫自己負責的區段；跨區塊的共用規則一律放在 js/rules.js。
3. 讀取成功但某區段為空時，該區塊顯示空狀態，不可視為讀取失敗。

## 5. 儲存流程（整份送出）

| 步驟 | 執行者 | 動作 | 檔案 |
| ---- | ------ | ---- | ---- |
| 1 | 使用者 | 在任一區塊修改內容，只改記憶體中的合輯 | js/edit.js |
| 2 | js/edit.js | 把所有區塊的資料組回整份合輯，並設定動作值 | js/edit.js |
| 3 | js/rules.js | 檢查所有欄位與動作值是否合法；有錯誤就不送出 | js/rules.js |
| 4 | js/api.js | 一次送出整份合輯與動作欄位 | js/api.js |
| 5 | 後端 | 取出動作欄位、驗證動作值、驗證合輯格式、依動作寫入、丟棄動作欄位 | 後端（尚未實作） |
| 6 | js/ui.js | 依成功旗標顯示結果；失敗時保留使用者輸入 | js/ui.js |

儲存規則：

1. 一次只送一個請求；不得先送部分區段再補送，也不得只送有修改的區段。
2. 清單項目的新增、刪除、排序都在記憶體完成，最後一次送出。
3. 送出的合輯必須包含全部 9 個區段；沒有資料的區段送空清單或空字串。
4. 有未儲存變更時，離開頁面前必須提示。
5. 儲存失敗時不得清空畫面或動作值，讓使用者可以重試。

## 6. 回應規則

| 情況 | 回應內容 | 前端處理 |
| ---- | -------- | -------- |
| 讀取成功 | 成功旗標為 true，並附上完整合輯（9 個區段齊全，不含動作欄位） | 依區段拆成頁面區塊並渲染 |
| 讀取失敗 | 只有成功旗標為 false，不提供錯誤碼 | 顯示讀取失敗訊息、重新載入與建立新履歷，不渲染任何資料 |
| 儲存成功 | 成功旗標為 true | 顯示已儲存，清除未儲存提示 |
| 儲存失敗 | 成功旗標為 false | 顯示儲存失敗訊息，保留使用者輸入 |

補充規則：

1. 不細分 400、404 等狀態碼，成敗只看成功旗標。
2. 讀取成功時回傳的資料一定是完整合輯；失敗時不含資料。
3. 儲存回應不需要回傳內容；前端以送出的合輯作為畫面來源。
4. 前端不得在讀取失敗時以空白資料覆蓋畫面或送出儲存。

## 8. 欄位值 → 動作對照

> 前端撰寫程式碼時的主要依據。判斷邏輯集中在 js/rules.js；動作只能呼叫 js/api.js、js/ui.js 或對應單頁檔。

### 8.1 動作欄位與封包

| 項目 | 值或條件 | 執行的動作 | 對應檔案 |
| ---- | -------- | ---------- | -------- |
| 動作欄位 | 修改 | 一般儲存：整份合輯覆蓋既有資料 | js/edit.js、js/api.js |
| 動作欄位 | 新增 | 讀取失敗畫面選擇建立新履歷後送出，建立新資料 | js/edit.js、js/api.js |
| 動作欄位 | 刪除 | 二次確認後送出；後端清除資料，不採用送出的內容 | js/edit.js、js/api.js |
| 動作欄位 | 其他 | 前端不得送出；若仍送出，後端回成功旗標 false | js/rules.js、後端（未實作） |
| 動作欄位 | 未提供或非法 | 前端阻止送出；後端回成功旗標 false，且不寫入任何資料 | js/rules.js、後端（未實作） |
| 封包 | 送出儲存 | 動作欄位與 9 個區段同層，一次送出 | js/api.js |
| 封包 | 讀取成功 | 回傳的合輯不含動作欄位 | js/api.js |

### 8.2 讀取與畫面拆分

| 項目 | 值或條件 | 執行的動作 | 對應檔案 |
| ---- | -------- | ---------- | -------- |
| 全域讀取 | 成功旗標為 true | 檢視頁拆分後渲染；編輯頁拆分後帶入表單，動作值設為修改 | js/api.js、js/view.js、js/edit.js |
| 全域讀取 | 成功旗標為 false | 顯示讀取失敗訊息、重新載入與建立新履歷，不渲染任何資料 | js/api.js、js/ui.js |
| 單一區段 | 空清單或空字串 | 該區塊顯示空狀態，其餘區塊照常顯示 | js/view.js、js/edit.js |
| 任一清單 | 新增、刪除、上下移 | 只修改記憶體中的合輯，不立即送出 | js/edit.js |
| 任一欄位 | 使用者輸入 | 即時套用格式規則提示，不送出 | js/rules.js、js/edit.js |

### 8.3 儲存與回應

| 項目 | 值或條件 | 執行的動作 | 對應檔案 |
| ---- | -------- | ---------- | -------- |
| 全域儲存 | 成功旗標為 true | 顯示已儲存，清除未儲存提示，動作值維持修改 | js/api.js、js/ui.js |
| 全域儲存 | 成功旗標為 false | 顯示儲存失敗，保留使用者輸入與動作值，可重試 | js/api.js、js/ui.js |
| 儲存前 | 任一欄位格式錯誤 | 不送出，聚焦第一個錯誤欄位 | js/rules.js、js/edit.js |
| 儲存前 | 沒有未儲存變更 | 不送出，提示目前沒有變更 | js/edit.js |

## 9. 驗證責任

| 層級 | 責任 | 依據 |
| ---- | ---- | ---- |
| 動作值 | 只接受新增、修改、刪除、其他；非法值不得送出 | js/rules.js |
| 前端即時提示 | 輸入時提示格式問題，避免送出明顯錯誤 | js/rules.js |

三處規則必須一致；本文件是單一來源，修改規則時必須同步本文件、js/rules.js 與格式定義檔。

後端驗證順序補充：驗證合輯前必須先取出動作欄位；格式定義與驗證腳本只針對 9 個資料區段，若把動作欄位一起送進驗證，會被視為未定義欄位而失敗。
