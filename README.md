# Resume_System_20261118（履歷系統）

以單一 JSON 合輯存放履歷資料，使用原生 HTML、CSS、JavaScript 建立的個人履歷檢視與編輯系統。

本文件只負責**導讀**：說明有哪些文件、AI 該用什麼順序讀、目前專案狀態。規則細節一律寫在 docs/專案規劃.md，不寫在這裡。

## 1. 文件角色

| 檔案 | 角色 | 裡面有什麼 | 什麼時候讀 |
| ---- | ---- | ---------- | ---------- |
| README.md | 導讀 | 文件清單、閱讀順序、目前狀態、工作規則摘要 | 每次開始工作時 |
| docs/專案規劃.md | 專案事實來源（產品＋設計） | 基本資訊、架構、資料規範、檔案清單、共用檔清單、頁面規劃、Markdown 與日誌規則、開發流程 | 動工前必讀 |
| docs/檔案關聯.md | 載入關係 | 哪個 HTML 載入哪些 CSS、JS，以及前置依賴與載入順序 | 新增或修改任何前端檔案時 |
| docs/API.md | 資料說明 | API 端點、傳輸封包、動作欄位、欄位定義、哪個值會觸發哪個動作 | 動到資料、欄位、動作或 API 時 |
| log/年-月-日.md | 日誌 | 當天每次動作的編號、動作、檔案、摘要、目的 | 需要知道最近改了什麼時 |

## 2. AI 閱讀順序（固定）

1. README.md（本檔）
2. docs/專案規劃.md — 先確認規則、共用檔案清單與目前階段
3. docs/檔案關聯.md — 確認要動的檔案與載入順序
4. docs/API.md — 確認資料欄位與「值 → 動作」對照
5. log/ 中日期最新的一份 — 確認最近狀態

補充規則：

| 情況 | 做法 |
| ---- | ---- |
| 尚未讀完上述 5 項 | 不得修改任何檔案 |
| 文件內容互相衝突 | 優先順序：專案規劃 → API → 檔案關聯 → 當日日誌 |
| 需要新增共用 CSS 或 JS | 先更新專案規劃的共用基礎檔案清單，再更新檔案關聯 |
| 完成任何動作 | 在當日日誌新增一筆紀錄，並確認日誌索引已登記 |

## 4. 工作規則摘要

1. HTML、CSS、JS 必須是各自獨立的檔案；禁止把樣式或程式碼寫進 HTML。
2. 共用樣式只有 css/base.css；共用程式碼只有 js/api.js、js/ui.js、js/rules.js；禁止重複實作相同邏輯。
3. 只有單一頁面會用到的樣式與程式碼，才能寫在該頁專用檔案。
4. 所有 Markdown 禁止寫 JSON 或程式碼，只能用文字與表格描述。
5. 未經明確指示，不得修改任何 Markdown 檔案。
6. 每次完成的動作都要寫入當日日誌，欄位為編號、動作、檔案、摘要、目的。
7. 儲存時一次送出整份合輯，並附上隱藏動作欄位（新增、修改、刪除、其他）。
8. 資料規則以 docs/API.md 為單一來源，前端不得自訂不同規則。

## 5. 名詞對照

| 名詞 | 意思 |
| ---- | ---- |
| 合輯 | 整份履歷資料，包含 9 個區段 |
| 區段 | 合輯根層的鍵，例如基本資料、學歷、經歷 |
| 共用檔 | 所有頁面都會載入的檔案 |
| 單頁檔 | 只有一個頁面會載入的檔案 |
| 成功旗標 | API 回應中唯一代表成功或失敗的值 |
| 傳輸封包 | 送出或讀回的完整內容；送出時包含隱藏動作欄位與 9 個區段，讀回時不含動作欄位 |
| 動作欄位 | 封包中用來說明本次是新增、修改、刪除或其他的隱藏欄位 |
